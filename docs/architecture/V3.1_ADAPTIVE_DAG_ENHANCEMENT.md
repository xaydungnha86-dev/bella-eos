## What Changed from v3.0

### v3.0: Simple Loop

```
Strategy → Simulation → FAIL → Strategy (always loops back here)
```

**Limitation**: Assumes problem is always in Strategy.

**Reality**: Problem could be in ANY node:
- Diagnosis (wrong root cause)
- Constraint (missed critical limit)
- Opportunity (insufficient alternatives)
- Strategy (poor combination)

---

### v3.1: Adaptive DAG with Multi-Path Feedback

```
          Simulation → FAIL
                │
    ┌───────────┼───────────┬───────────┐
    ▼           ▼           ▼           ▼
Retry Diag  Retry Const  Retry Opp   Retry Strat
```

**Innovation**: System analyzes failure and loops back to the **root cause node**, not just Strategy.

---

## Key Enhancement: Failure Analysis Engine

### 4 Symptom Detectors

1. **Wrong Diagnosis Detector**
   - All strategies fail
   - EV far below goal (>50% gap)
   - Opportunities don't address root causes
   - **Action**: Retry Diagnosis node

2. **Missed Constraint Detector**
   - Strategy violates implicit constraint
   - Simulation reveals hidden bottleneck
   - Policy violation
   - **Action**: Retry Constraint node

3. **Insufficient Opportunities Detector**
   - Best strategy still below goal
   - Few high-impact options (<3)
   - Opportunities clustered (lack diversity)
   - **Action**: Retry Opportunity node

4. **Poor Strategy Detector**
   - Internal strategy conflicts
   - High risk reduces value
   - Few alternatives explored
   - **Action**: Retry Strategy node

## Example: Multi-Path Retry in Action

### Iteration 1: Wrong Diagnosis Detected

```
CEO Goal: "Tăng doanh thu 30%"

Diagnosis: "Revenue flat due to POOR ACQUISITION" ❌ WRONG
Opportunity: [Facebook Ads, Google Ads, TikTok]
Strategy: Aggressive Acquisition (180M budget)
Simulation: EV = 0.8B, P(Success) = 35%
Result: FAIL

Failure Analysis:
  ✅ All strategies failed (score 0.8)
  ✅ EV 47% below goal (score 0.6)
  ✅ Historical data shows churn 55% (score 0.7)
  Total: 0.93 → HIGH confidence wrong diagnosis

Recommendation: Retry Diagnosis Node ⭐
```

### Iteration 2: Re-Diagnosed, Now Constraint Issue

```
Diagnosis: "Revenue flat due to HIGH CHURN (55%)" ✅ CORRECT
Opportunity: [Win-back, Loyalty, Upsell, Weekend, Email]
Strategy: Retention-First (150M budget)
Simulation: EV = 1.5B, P(Success) = 75%
Result: BORDERLINE (just at threshold)

Failure Analysis:
  ✅ Only 75% confidence (borderline)
  ✅ Only 5 opportunities (need 10+)
  ✅ Only 3 high-impact used
  Total: 0.65 → MEDIUM confidence insufficient opportunities

Recommendation: Retry Opportunity Node ⭐
```

### Iteration 3: Expanded Opportunities, PASS

```
Opportunity: [10 options including TikTok pilot, Referral]
Strategy: Balanced (Win-back + Upsell + Weekend + TikTok)
Simulation: EV = 1.706B, P(Success) = 80%
Result: PASS ✅

Total Iterations: 3
Retries:
  - Iteration 1 → 2: Diagnosis (wrong root cause)
  - Iteration 2 → 3: Opportunity (insufficient options)
```

**Key Point**: System didn't blindly retry Strategy. It identified:
1. First, diagnosis was wrong → fixed at source
2. Then, opportunity set was weak → expanded
3. Finally, converged with correct diagnosis + rich opportunities

## Implementation Complexity

### Low: Uses Existing Graph

No new nodes required. Enhancement is in **loop orchestration logic**:

```typescript
// OLD (v3.0)
if (simulation.fail) {
  strategy = refineStrategy(strategy);  // Always retry Strategy
}

// NEW (v3.1)
if (simulation.fail) {
  const analysis = await analyzeFailure(simulation, context);
  
  switch (analysis.recommendedRetryNode) {
    case 'diagnosis':
      diagnosis = await retryDiagnosis(context);
      opportunities = await retryOpportunity(diagnosis, constraints, context);
      break;
    case 'constraint':
      constraints = await retryConstraint(context);
      break;
    case 'opportunity':
      opportunities = await retryOpportunity(diagnosis, constraints, context, { expand: true });
      break;
    case 'strategy':
      // Implicit retry in next iteration
      break;
  }
}
```
